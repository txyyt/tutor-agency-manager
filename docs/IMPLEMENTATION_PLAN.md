# 家教中介管理系统：实施与验收方案

版本 V1.3；日期 2026-09-30；项目目录 `D:\tutor-agency-manager`。

本方案为后续开发、测试、验收的业务基准。已确认业务优先；普通技术选择按默认方案推进。不得把缺失功能或未执行测试当作已完成。

## 1. 目标与范围

开发中文内部管理 Web 应用，第一版本机浏览器使用。中介手动录入、上传简历、在微信发送模板和导出文字；系统负责持久化、关联、计算和校验。

必须实现：粘贴家长/老师已填模板自动解析建单或报名、订单与报名增查改、搜索筛选分页、群内招募文字复制/TXT下载、候选简历摘要、附件、推荐试课、收退款与结清、完成取消、90天自动及手动清理、界面导出/导入完整数据库备份、每日自动备份、真实测试和使用说明。

不做：公开填表网站、家长/老师登录、长期个人档案、独立费用表、自动微信发送、AI简历解析、课程与授课工资管理、在线支付、云部署、多设备同时办公。

薪资为授课报酬，与保证金、中介费分开。第一版只登记中介费用，不结算课程薪资。

## 2. 已确认口径

- 只有两张业务表：订单 `orders`，老师报名 `applications`。
- 一份需求一单。两个孩子、重复家长、不同需求分别填表录入。
- 一份针对指定订单的简历一条报名。重复老师、不同订单分别录入，不合并、不去重。
- 一单多报名；一条报名仅关联一单，报名表保存订单ID。
- 新订单直接招募中，新报名直接已报名。
- 家长和大学生的微信、电话均必填；大学生无可授课区域字段。
- 所有中介费用由大学生老师支付；试课成功保证金抵扣中介费。
- 试课失败、老师主动退出、家长取消退回保证金。
- 跳过试课是双方直接确认合作，不是尚未安排试课或取消。
- 确认合作且费用结清后完成中介任务，不等待全部课程结束。
- 最后实际修改后90天清理；查看、导出、下载不延期。保留在办、待收退款和关联记录保护。
- 试课未通过只记状态，不要求原因。
- 支持直接粘贴微信中已填写的家长/老师模板，自动识别并填入新记录，不要求逐字段重新输入；有缺失或歧义时只需补正相关项。
- 界面可直接导出完整数据库备份、选择备份包导入恢复；每日自动生成一次备份，包含简历附件，不只备份文字记录。

## 3. 状态、动作与完整流程

### 3.1 订单状态

| 代码 | 中文 | 含义 |
| --- | --- | --- |
| recruiting | 招募中 | 唯一进入群内招募导出的状态 |
| reviewing | 家长挑选中 | 暂停群内招募，挑选候选 |
| awaiting_trial | 待试课 | 已安排本次试课老师 |
| trialing | 试课中 | 等待实际试课反馈 |
| completed | 已完成 | 合作确认、费用结清、成交报名明确 |
| paused | 暂停 | 暂停跟进，不开始清理 |
| cancelled | 已取消 | 停止招募，仍允许处理退款 |

主流程：招募中 → 家长挑选中 → 待试课 → 试课中 → 家长挑选中（显示试课通过，待确认/结算）→ 已完成。无需新增一个正式合作状态。

- 招募中/家长挑选中可互转；报名、导出、生成候选摘要、标已推荐均不自动改变订单状态。实际停止招募点击“开始家长挑选”。
- 招募中或家长挑选中均可直接安排试课，避免强制经过不必要步骤。
- 当前老师失败/退出才清除当前引用，选择回到挑选或招募，默认挑选；其他候选退出不改变当前老师或订单阶段。
- 在办订单可取消；第一版只允许招募中/挑选中暂停，保存暂停前状态用于恢复，防止隐藏进行中试课。
- 完成/取消不能通过普通下拉框绕过校验。完成或取消后不能再报名或招募；新需求新建订单。取消仍可退款和修正资料。

### 3.2 报名状态

| 代码 | 中文 | 触发 |
| --- | --- | --- |
| submitted | 已报名 | 新建 |
| recommended | 已推荐 | 实际发送后手动或批量标记 |
| awaiting_trial | 待试课 | 选定并安排试课 |
| trial_passed | 试课通过 | 实际试课后通过 |
| trial_failed | 试课未通过 | 实际试课不满意 |
| withdrawn | 主动退出 | 老师主动退出 |
| order_closed | 订单已结束 | 非成交候选结束跟进或订单取消 |
| direct_cooperation | 直接合作 | 明确跳过试课直接确认合作 |

- 已报名可直接安排试课，不强制先已推荐。
- 试课进行期间报名仍待试课，订单状态表示试课中；试课通过/未通过须订单已开始试课。
- 每单同时只有一位当前试课或待结算合作老师，以 current_application_id 标识。其他候选保留，不同时安排第二位试课。
- 当前老师失败/退出清除当前引用；通过后订单回到家长挑选中，显示“试课通过，待确认/待结算”，保留当前引用等待完成，不继续显示试课中。直接合作同样家长挑选中等待结算。
- 完成后成交报名保留通过/直接合作；其他有效候选改订单已结束，失败/退出保持原状态。
- 取消时其他有效报名结束，失败/退出保持原状态。
- 终止报名不重新激活，重新投递新建报名。
- 直接合作只从招募中/挑选中且没有当前试课老师时选择；设当前报名，订单进入家长挑选中等待结算，不假造试课中状态。取消订单清空当前引用。
- current_application_id非空时禁止继续招募、暂停、安排其他人或重复直接合作；通过/直接合作后未完成前仍可明确登记该老师退出或取消整单，并按未完成退款流程处理。完成后禁止退出/取消，后续授课不在本系统范围。
- 标已推荐只允许已报名，已推荐重复标记为无变化；不能把待试课/通过/终止记录降回推荐。所有状态动作校验订单与报名组合及当前引用，不能任意提交目标状态。

### 3.3 操作顺序

1. 家长重新填模板，中介创建订单，立即招募中。
2. 随时导出全部招募中订单，复制或下载文字，手动粘贴微信群。
3. 老师报订单编号、投当次简历，中介录入报名和附件。
4. 多选候选生成摘要，手动发家长，发送后标已推荐；开始挑选时明确切换订单状态。
5. 选定一位，安排试课，设定费用、登记实收保证金，开始试课。
6. 失败：改未通过、产生待退款，实际退后登记；继续挑选或招募。退出同样退保证金。
7. 通过：标试课通过，明确确认合作，保证金抵扣，补收余款；直接合作走单独动作。
8. 完成前统一校验成交老师结清、其他报名退清，记录成交报名，结束其他候选。
9. 家长取消：取消订单并结束有效报名，已收款产生待退款；不自动假装已退。
10. 按最后实际修改90天清理，保护未完成业务及未结算记录。

### 3.4 完成订单必须事务校验

- 成交报名属于本单且为当前报名，状态通过或直接合作。
- cooperation_confirmed_at 已设置；通过不自动代表合作确认。
- 成交报名费用设定完整，净收恰好等于中介费；其他报名净收均为零。
- 一个事务记录成交ID和完成时间、结束其他有效候选、更新实际变化记录时间。
- 不满足时说明具体报名及缺少条件，不只提示“失败”。

### 3.5 状态一致性约束

| 场景 | 订单/当前引用/报名必须一致 |
| --- | --- |
| 安排试课 | 原订单招募或挑选，无当前引用；报名已报名或已推荐；设置该报名为当前，双方待试课 |
| 开始试课 | 订单待试课，当前报名待试课，保证金已满足；仅订单改试课中 |
| 通过/未通过 | 订单试课中且操作对象等于当前；通过回挑选保留引用，未通过回挑选/招募清引用 |
| 非当前退出 | 只变该报名及其退款显示，订单状态与当前引用不变 |
| 当前退出 | 未完成订单，改退出、清引用、回挑选/招募，费用成为待退款 |
| 直接合作 | 订单招募/挑选且无当前；报名已报名/已推荐；设置当前、直接合作、确认合作时间，订单挑选 |
| 完成 | 当前通过/直接合作且确认、全单费用满足；成交引用等于当前，双方引用保留，其他有效报名结束 |
| 取消 | 未完成订单；清当前、无成交引用、有效报名结束；发生过收款的报名仍可退 |

已完成必须有成交引用且与当前一致；已取消两项引用均为空；暂停/招募必须无当前引用；待试课/试课中必须有本单待试课报名作为当前。挑选中可无当前或当前为通过/直接合作。所有组合在动作事务和恢复校验中一致执行。

## 5. 费用算法与保护

定义D=保证金实收−实退，S=补款实收−实退，F=应收中介费，N=D+S为当前净收。

- 通过或直接合作且确认合作后：抵扣=min(D,F)，待补=max(F−N,0)，多收待退=max(N−F,0)。未确认时只显示保证金已收，不提前算成已赚中介费。
- 失败、退出、未成交结束、订单取消：待退=N，退清后净收应为0；误收补款也需退清。
- 完成要求成交报名N=F，其他报名N=0。

输入规则：

1. 金额非负整数分，最多两位小数，禁止负数、NaN、浮点累计。
2. 各项累计退款不得超过各自累计收款。
3. 收保证金前设F和计划保证金；计划保证金不超过F。允许登记实际少收金额。
4. 只有通过/直接合作且已确认，才允许补收；补款不超过待补金额。
5. 取消/失败/退出后禁止继续收款，只允许退款。
6. 收款后下调费用必须显示产生的待退金额，不能通过改收费掩盖多收。
7. F为空不能完成；明确填写F=0的免费个案，合作确认且N=0可完成，不将缺失金额自动视作免费。
8. 收/退款按钮输入本次实际金额，事务内累加。重复请求不得重复收钱，具体实现见技术章节。
9. 已完成财务锁定，允许修正一般资料；完成后费用变更不在第一版流程内，不提供直接改钱绕过校验的入口。
10. 费用主显示为累计值和最近日期，另在本报名JSON内存操作ID及更正证据，不建立独立财务流水模块；界面必须清楚标“累计”和“最近”。
11. 新收保证金只允许当前待试课报名且订单未开始/结束；其他候选不提前收。开始试课必须F和计划保证金都明确，即使均为0也要实际填写。
12. 收费调整时计划保证金与F保持相容；已有净收高于调低的F/计划金额是合法待退款状态，不回写或抹掉历史收款。收款上限只限制新增收款动作，不能让恢复校验拒绝真实的多收待退记录。
13. 录入错误使用“更正登记”，只在未完成订单允许，填写更正理由并展示前后累计金额；真实退款仍走退款动作，不用虚构退款修正输入错误。累计值仍非负、退款不超收款，更正记录保存于finance_operations_json；取消订单只允许退款或带理由修正，不允许真实新增收款。

开始试课前，保证金净收须达到本次计划保证金；计划保证金明确为0则无需收取。新增收款允许分次登记，但不得使净收超过当时计划值；计划后来下调产生的超额按待退款处理。安排试课与实际开始试课分开，少收期间保持待试课。取消后仍可退清。

示例：F=300元，实收保证金100元；通过并确认后抵扣100、待补200；补200后可完成。失败则待退100，实际退100后待退0。

## 6. 90天自动清理

### 时间与独立报名

到期条件 `updated_at <= now - 90×24小时`；测试可注入时钟。真实字段、状态、费用、附件变化才更新时间；无变化保存、查看、复制、导出、下载不更新。

报名修改不伪造订单修改时间，但整单清理检查全部关联报名。失败/退出/订单已结束报名到期、N=0、无待退款且不被当前/成交引用时，可独立清理；在办订单下满足条件的失败/退出报名也可删除。其他报名不独立清理。

### 整单清理

仅完成/取消订单，订单及全部剩余报名都到期，且财务条件满足才可删除：完成时成交报名已结清、其他净收0；取消时全部净收0。招募/挑选/待试课/试课/暂停始终保护。

成交报名随整单删，不能单独删。事务中先清引用再删报名及订单；不会留下半套关系。

### 执行方式

- 服务启动补做一次，此后每24小时自动执行；服务停止期间不执行，重启补做。不安装系统级定时任务。仅在重新核验后确有可删除记录时生成清理前备份；无候选不生成整库备份。备份失败则跳过删除并报告，避免没有恢复点。
- 提供预览、立即执行、删除/跳过/失败计数及保护原因。执行重新核验，预览后修改不能仍被删。
- 数据事务成功后删附件，路径严格限制在项目数据附件目录，禁止跟随链接删除外部文件。
- 文件失败必须报告并下次重试已无引用文件清理；日志不复制个人资料正文。
- 自动运行无需人为确认，手动执行展示影响确认；真正修改保留期才延期。
- 删除运行库和原附件是永久删除；人工备份不自动同步删除。恢复备份后重新检查到期，使用文档明确此边界。

### 备份与恢复（第一版必需）

#### 导出与格式

- 页面按钮“导出完整备份”生成并下载ZIP；可从自动备份列表下载已有备份。ZIP内包含SQLite一致性快照、全部仍被引用的简历附件、manifest.json，不包含历史备份本身、node_modules、日志和密钥。
- 文件名示例 tutor-backup-20260930-143000-唯一后缀.zip；不能覆盖同名历史包。清单包括格式版本、数据库schema版本、应用版本、UTC创建时间、显示时区、订单/报名/附件数量、每个文件相对路径和SHA-256校验值。
- 单纯导出招募TXT不能代替数据库备份；记录原始模板、金额、状态、引用、时间、编号序列都必须完整包含。
- 导出只读，不刷新记录updated_at。备份期间通过统一维护锁短暂暂停业务写入及附件变更、等待在途写操作完成，读取不受影响；必须在锁内把数据库一致性快照和所有对应附件复制至独立快照临时目录，确认齐全后释放锁，再仅从快照目录打包。不能仅收集原附件路径后解锁，否则附件可能在打包前被删除。
- 先写临时包、完成校验后原子改名为完成文件；失败包不进成功列表、不替代上次成功备份。备份包含个人资料，不提交Git。

#### 每日自动备份

- 默认每天02:00（Asia/Hong_Kong）一次；当天首次启动如尚无该日成功自动备份，立即补做，不能补造过去停机日期的历史快照。
- 只在系统运行时执行。关闭系统或电脑关机时无法生成备份，下次启动补做当前快照；不声称关机也能定时备份，不额外安装Windows计划任务。
- 默认写项目数据目录下backups/daily，界面显示真实绝对路径和最近成功时间。日备份成功后才持久化当日标记；调度元数据用配置JSON保存，不增加业务表。
- 当天已成功自动备份不重复生成；失败显示错误并在运行期间5分钟后重试。允许手动立即备份，不受每日一次限制。
- 默认自动日备份保留最近30份成功包；成功生成新包后才清理超过数量的自动日备份。手动导出不自动删除；恢复前/清理前属于自动安全备份，单独保留最多10份且不超过30天，维护页面明确显示期限。仅在已有本次验证成功的新备份时轮换，备份失败不删除旧恢复点。避免清理每日创建永久全量副本。
- 用户可在界面设置自动备份目录和保留份数（正整数，默认30）。自动备份目录必须独立于活动数据代、附件、临时快照和导入暂存目录，不能互为祖先/子目录，不允许根目录或目录链接；设置失败保留原设置。仅轮换登记为本应用自动备份且校验通过的文件，禁止按扩展名扫描删除其他ZIP。验收及开发仅用项目内临时目录。
- 本地备份主要防误操作、文件损坏；使用指南说明将导出包另存其他磁盘/U盘可用于电脑或磁盘故障后的恢复，系统不自动上传云端。

#### 导入恢复

- 第一版支持本系统完整ZIP备份，导入语义是恢复到该备份时点，替换当前订单、报名与附件，不合并、不追加。明确显示备份时间、数量和“备份之后新增/修改的数据将被替换”，用户在界面确认后执行。
- 文件上传至隔离临时目录并校验：包格式、清单、校验值、SQLite integrity_check、foreign_key_check、两张业务表和字段、关联/金额/状态不变量、附件齐全、编号序列。较旧已支持schema先在临时副本迁移；未知或更新版本拒绝，不能直接执行包内脚本。
- 限制上传大小默认1GB、解压后总量默认2GB，限制条目数量100,000；界面可调整上限，超过时说明原因且不触及当前数据。导出检查本机当前导入上限，超限包需在导出前明确提示所需调整值，不承诺该包在默认设置下可直接恢复。拒绝路径穿越、绝对路径、目录链接、重复或Windows大小写冲突路径及不在清单的载荷；支持正常中文原文件名。
- 校验预览不改当前业务数据。确认执行时进入维护状态，阻止新写入/清理/备份并等待在途操作完成；先自动生成当前数据的恢复前完整备份，失败则终止导入。
- 数据库和附件作为一套恢复：在独立数据代目录准备、迁移并验证，原子切换活动数据目录指针后重开连接；不采用先覆盖数据库、再零散拷附件导致半恢复的方式。维护锁持续至整套可用，失败切回原代。
- 用可持久化的恢复操作状态处理进程意外退出：重启后明确选择已完整验证的新代或原代，不留下数据库来自A、附件来自B；重复确认同一恢复操作不能反复覆盖后来新增数据。
- 恢复保留原created_at、updated_at和已有编号，不把全部记录改成今天。下一编号取本机已发编号高水位与备份高水位较大值之后，不能恢复旧备份后复用已经发到微信群的编号。高水位保存于数据代外配置并随备份清单导出；换电脑恢复仅能保证备份已知范围不复用，不能知道备份之后其他电脑发过的编号。恢复成功后自动检查到期规则；实际清理按第6节先备份再删，报告恢复条数和到期清理条数，不把清理失败当成恢复失败再盲目回滚。
- 成功生成全新的data_epoch并清空旧页面缓存、重新加载列表；所有写请求携带该代标识，恢复前旧页面/在途重试一律拒绝，避免旧version恰好匹配恢复后的version而覆盖数据。预览令牌绑定备份哈希及数据代，限时单次使用。失败显示具体原因、当前数据仍可用。备用命令行与界面共享同一校验和恢复服务。

#### 与90天清理的关系

运行数据按90天规则删除，备份是历史快照，会保留当时已存在的资料；日备份和自动安全备份按各自规则轮换，用户手动保存的包不自动删除。清理前和恢复前备份可在维护页明确展示期限、下载及手动删除，不能隐瞒历史快照仍有已清理资料。

恢复用的旧数据代不是另一个永久备份：切换后重开连接、校验成功并确认为完成后，等待旧读请求结束，清理未激活旧代；失败保留完整原代用于回滚。重启处理恢复日志后再清理未引用的临时目录。自动备份、配置、操作日志位于数据代之外，不因为切换一起丢失。清理只针对本应用登记且严格验证的目录，不递归扫描其他用户目录。

### 粘贴模板自动录入（第一版必需）

入口：订单列表“粘贴家长模板建单”；订单详情“粘贴老师模板报名”；全局“粘贴老师模板”通过原文订单编号定位订单。

操作：粘贴一份已填写的模板 → 自动解析并生成填写好的新记录表单 → 显示解析结果与需补正项 → 点击保存创建记录。无需逐项重新录入；解析阶段不写业务库，保存成功家长订单为招募中、老师报名为已报名。保留普通表单录入方式。

解析规范：

1. 使用TypeScript确定性文本解析器，不依赖AI、付费API、外部网络；以WECHAT_TEMPLATES.md的字段名为基准，按名称而非固定编号识别。
2. 支持中文/英文冒号、CRLF/LF、空行、首尾空格、可选数字序号、调整字段顺序、同一字段多行内容。支持明确别名：微信号→微信、手机号/联系电话→电话。不得把单个“联系方式”猜成微信和电话两项。
3. 模板标题、固定分组标题、固定说明文本可忽略；未填写的下划线及保留的“是 / 否”“线上 / 线下”等选择提示视作缺失，不当有效答案。
4. “150元/小时”“每周2次”“每次1.5小时/90分钟”转为整数分/次数/分钟；金额用字符串精确转换，不走浮点累计。模糊的薪资范围保留原文并要求选定金额，不能擅自取最低值。
5. 是/否、线上/线下、性别规范化；明确日期可转换，协商可留空；“下周一”等相对或有歧义日期保留原文并提示补正，不静默猜日期。
6. 微信、电话、教学经验等保留原内容，不能把电话当数值丢失前导零/区号，不能丢弃多行简历正文。
7. 公共区域/时间/要求显示在解析后的表单，仍遵循公开/内部字段分离。公共区域不从详细住址盲目整段复制；无法明确提取大致区域时要求操作人补正。最终保存使用与普通表单相同的必填及业务校验。
8. 老师订单编号精确匹配存在且允许报名的订单。订单详情入口的当前订单与原文编号不一致时阻止保存，不偷偷替换编号；编号缺失/不存在、订单完成/取消/暂停时给出具体提示。招募中/挑选中/待试课/试课中可接收候选报名，但不自动改变进度。
9. 未识别字段、重复冲突字段、缺失必填和无效值逐项显示；保留原文和已识别值。冲突不得静默取最后一项；修改后再校验保存。解析失败不创建半条记录。
10. 一次只处理一份模板，检测多份标题或多个冲突订单编号时提示分开粘贴，不把多人的内容混到一条记录。输入长度上限50,000字符，超限明确提示。
11. 同一次保存的重试、双击不得重复建记录，使用创建请求ID在对应业务表唯一约束；允许同一人重新投递和不同单独立记录。相同原文已存在可提示疑似重复，但不以姓名/微信或全文Hash禁止真实的新投递。
12. 文本中的附件文件名/“见附件”不代表文件已上传；提示另行选择本机文件上传。不做图片OCR或PDF自动解析，不下载原文中的链接。
13. 未填说明文本必须按固定模板精确识别，不删除所有括号行；老师正文中的括号、冒号或“年级：”不能被误判成新顶级字段。编号字段优先识别，嵌套说明字段（是否可协商、期望薪资、试课限制）有明确归属；识别不了则保留并提示，不丢内容。

预览/补正是创建表单的一部分，不新增审批流程。解析输出为draft、fieldErrors、warnings、unrecognizedFields及原文，保存前后均通过统一字段校验。

## 8. 技术默认方案

在现有项目内开发，不另建Sites，不依赖付费服务。

- React + TypeScript + Vite前端；Node.js + TypeScript + Express后端，统一服务端校验，可用Zod。
- 开发语言明确采用TypeScript：前端、后端、模板解析和业务测试统一使用TypeScript，数据库迁移使用SQL。Node.js是后端运行环境，React/Express是框架，SQLite是数据库；不改用Python后端或混搭其他主业务语言。
- SQLite持久化，优先本机Node的node:sqlite，实现前验证API；兼容问题允许等价SQLite驱动，锁定版本，不改业务。
- 参数化SQL、事务、外键、迁移；不只用localStorage保存业务。
- 单元测试验证规则；集成测试用临时SQLite；Playwright浏览器E2E。
- 构建后由后端提供页面，默认 http://127.0.0.1:3000，只监听回环地址。单机内部使用，无账号系统；公网/多设备部署后续另做认证。
- PowerShell7、UTF-8，不依赖Bash/CMD/WSL；依赖使用前检查官方兼容信息，提交lockfile。

目录：src/client、src/server、src/shared、migrations、tests/unit、tests/integration、tests/e2e、scripts、docs；data为本机数据库和附件，不入Git。

数据布局明确为data/runtime.json（活动代与data_epoch等配置）、data/generations/<随机代ID>/database.sqlite及attachments/、data/backups/、data/staging/。备份/配置/暂存均在活动代外，按登记记录回收旧代。CLI restore的--from接受本系统ZIP文件路径，不以任意目录内容直接覆盖数据库。

必须提供以下命令：

```text
npm run dev
npm run build
npm start
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run cleanup:preview
npm run cleanup
npm run backup
npm run restore -- --from <完整备份ZIP路径>
```

编号用持久化单调序号/SQLite AUTOINCREMENT，不按现存行数，历史编号不复用；SQLite内部表不是额外业务表。迁移可用user_version，不擅自增加家长、老师、费用表。

实体变更带version和当前data_epoch，冲突提示刷新，不静默覆盖。涉及两条记录的业务动作同时校验订单与目标报名版本，数据库写事务内检查当前引用。每次收退附一次性operationId，执行前查询报名内finance_operations_json：相同ID且相同载荷返回原结果，不增加金额；相同ID不同载荷拒绝。累计字段和操作记录在同一事务提交，进程重启仍幂等；不只依赖内存缓存。前端不静默重放新的财务操作。

一套数据目录仅允许一个服务进程持有运行锁，第二个实例启动明确拒绝；备份/恢复不能与另一个端口实例各自操作同一库。data_epoch及活动代指针、恢复日志原子写入配置JSON，不增加业务表。

维护锁只在最外层获取一次，备份/恢复/清理使用已持锁的内部方法，避免恢复调用备份、清理调用备份时重复获取同一锁而死锁。恢复期间暂停新读写（进度端点除外），等待旧连接关闭后切换；读取备份阶段可继续，恢复阶段不能混读两代。

单机无登录也要限制HTTP请求来源：只允许本应用Origin/Host，变更操作校验会话CSRF令牌、拒绝不可信跨域请求和宽松CORS；不允许其他网页访问本机端口来恢复或删数据。首次页面加载建立本机会话，无需用户注册登录。

附件受控端点下载，限制路径、大小、类型，不按HTML渲染用户文本。业务写入、附件变更、清理、备份、恢复使用统一维护锁。备份采用SQLite一致性备份方式并包含附件；界面恢复自动进入维护状态，准备并验证新数据代、先备份当前数据再原子切换。仅自动备份可以写用户明确选定的目录，恢复活动数据仍留在应用数据目录内。

.gitignore忽略数据库/WAL/SHM、附件、备份、日志、测试产物、node_modules、构建目录及敏感配置。仅虚构演示/测试资料入Git。

### API与错误契约

以下为实现基准，可采用等价路由，但不能遗漏动作；界面和测试使用同一业务服务，禁止界面直接写数据库。

| 路由 | 作用 |
| --- | --- |
| GET /api/orders | 搜索、筛选、分页，返回items/total/page/pageSize |
| POST /api/orders | 创建招募订单 |
| GET /api/orders/:id | 订单、候选列表、费用汇总 |
| PATCH /api/orders/:id | 只改一般资料，携带version，状态和钱不通过此入口绕过 |
| POST /api/orders/:id/actions | review/recruit/pause/resume/start-trial/cancel/complete等受控动作 |
| POST /api/orders/:id/applications | 创建本单报名 |
| GET/PATCH /api/applications/:id | 详情与一般资料修改；不允许改所属订单 |
| POST /api/applications/:id/actions | recommend/schedule-trial/pass/fail/withdraw/confirm-cooperation/direct-cooperation |
| POST /api/applications/:id/finance | 设置收费、实际收退，携带version和operationId |
| POST /api/orders/:id/recommendations | 校验多选报名均属于本单，生成摘要或批量标推荐 |
| GET /api/exports/recruiting | 全部招募中，支持text/plain UTF-8下载 |
| GET /api/templates/:name | 家长、老师、费用告知模板 |
| POST /api/imports/parse | kind=parent/teacher、text、可选contextOrderId；仅解析返回草稿/错误/警告，不写库 |
| POST /api/applications/:id/attachments | multipart上传，服务端检验 |
| GET/DELETE /api/applications/:id/attachments/:fileId | 受控下载/删除附件 |
| GET /api/applications/:id/attachments/:fileId/preview | PDF/图片受控inline预览，不支持时下载回退 |
| GET /api/cleanup/preview | 将删除与受保护项目及原因 |
| POST /api/cleanup/run | 重新核验后执行，返回计数和错误 |
| GET /api/dashboard | 业务与待收退款统计 |
| GET /api/backups | 成功备份列表、最近状态、设置，不列失败临时包 |
| POST /api/backups | 手动创建完整备份，返回操作ID/状态 |
| GET /api/backups/:id/download | 受控下载ZIP，不接受任意文件路径 |
| PATCH /api/backups/settings | 自动备份目录和保留数量校验后保存 |
| POST /api/restores/validate | 上传完整ZIP，只校验并预览，返回限时恢复令牌 |
| POST /api/restores/commit | 用户确认后以令牌执行恢复，备份当前数据、维护锁、原子切换 |
| GET /api/maintenance/operations/:id | 查询备份/恢复进度和结果 |
| POST /api/applications/:id/finance/corrections | 未完成订单下带理由更正登记，记录前后值与操作ID |

普通错误返回{code,message,fieldErrors?}；400为字段校验、403为不可信来源/令牌、404为不存在、409为状态/版本/数据代冲突、413为文件超限、503为维护暂不可用。失败不能部分写库。前端显示可理解中文原因，重试不丢表单。批量推荐要么全部校验通过再执行，要么无变更，不半批成功。

粘贴保存复用订单/报名创建接口，附source_template_text和creation_request_id；不得信任解析预览绕过服务器校验。服务端检查订单关联和创建请求唯一性。

### 明确的第一版默认选择

以下为便于直接实施的默认实现细节，不是额外主业务：单机无登录、一单同时一位试课、计划保证金不超过中介费、明确免费个案、最多5个10MB附件、版本冲突保护、无完成订单重新开启。若未来需要多名老师同时试课、多设备或已完成后修改费用，应另行扩展，不在开发中擅自改变现有流程。
